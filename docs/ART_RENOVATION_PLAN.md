# 《纸上浦江》美术质量全面改造计划

- 文档日期：2026-10-21
- 计划文件：`docs/ART_RENOVATION_PLAN.md`
- 当前状态：实施中；进度与验收证据见 `ART_RENOVATION_PROGRESS.md`。未完成的阶段不得提前标记通过。
- 改造目标：保留 360° 环绕、三时段和现有交互，将画面从简化几何沙盘升级为具有建筑细节、城市层次和水彩光影的三维风景。
- 视觉依据：用户提供的图2。
- 运行取向：桌面画质优先，手机采用简化效果。

## 一、目标、边界与验收原则

### 1.1 最终画面目标

默认视角以黄浦江连接外滩与陆家嘴，形成完整城市风景：

- 城市、江面和天空占据主要画幅，取消当前大面积灰色留白。
- 默认视角不展示厚底座，环绕时不暴露悬空地块、场景断面和空白背面。
- 外滩体现连续街区、古典建筑和丰富屋顶；陆家嘴体现地标轮廓、幕墙差异和高低层次。
- 水面具有随视角与光照变化的碎光、倒影、岸边层次和船尾波。
- 水彩与水粉效果贯穿建筑、树木、天空和水体，保持整体清晰与通透。
- 近景有细节，中景有结构，远景通过色彩与空气透视自然退后。

图2作为构图、色彩、建筑丰富度和绘画氛围的目标，不要求各环绕角度与单张参考图逐像素一致。

### 1.2 保留的能力

保留现有十三处地标、自由环绕、触控缩放、四个镜头预设、地标介绍与聚焦、标签遮挡、截图、画质切换、快捷键、减少动态效果和资源异常提示。

保留白昼、暮色、入夜及可中断的连续过渡。

继续采用纯前端、本地运行和静态交付，不新增账户、服务器或在线发布流程。

### 1.3 本次不包含

- 建筑室内、第一人称步行和全城地理精确复刻。
- 实时天气、真实交通和城市仿真。
- 将实时三维替换成整幅二维背景。
- 与美术改造无关的界面重设计。
- 默认接入付费素材平台或按量计费的外部生成服务。

### 1.4 验收规则

功能、性能、资源完整性和美术质量分别验收。

**“调用过 image”“资源加载成功”“测试通过”均不能代替画面质量达标。**

主画面与局部样片完成视觉验收后，才扩展同类资产到全城。视觉验收以实际运行截图为依据，概念图不作为最终成品证明。

## 二、现状与技术路线

### 2.1 当前基础

现有工程采用 Vite、TypeScript、Three.js，已经具备：

- 三维城市、十三处地标和固定种子配景布局。
- 图片贴图加载、天空、阴影、水面反射及夜景 Bloom。
- 三时段状态、交互控制、截图与异常恢复。
- 功能检查、性能记录和环绕截图脚本。

主要差距在于：

- 建筑立面大量依靠规则窗格，造型和装饰不足。
- 美术资源主要作为通用表面纹理，未充分针对建筑结构制作。
- 默认构图突出孤立底座，缺乏城市延伸与远景层次。
- 简单卡通材质与低对比纹理无法形成目标中的水彩光影。
- 原有验收未充分约束参考图与最终画面的视觉差距。

旧性能记录来自其他设备与环境，仅保留为历史资料，不能作为改造后的性能结论。

### 2.2 选定路线

采用：**Three.js 实时三维 + 独立建筑资产 + image 专用美术资源 + 绘画材质与后处理。**

继续沿用现有 WebGL 渲染和交互基础，不同时迁移游戏引擎或渲染后端。

建筑离线制作采用 Blender，运行资产采用 GLB；通用街区通过模块化资产组合与实例化布置。程序负责组装、实例化和动画，核心建筑的视觉细节由独立资产承载。

实施阶段先建立离线制作工具链；缺少工具时应报告依赖，不能悄悄退回现有方块建筑并视为完成。

### 2.3 场景组织

| 层级 | 内容 | 制作方式 |
|---|---|---|
| 核心区 | 十三处地标、主要沿江建筑和步道 | 独立模型、专用贴图、完整四面与屋顶 |
| 街区区 | 中近景配景、道路、植被和码头 | 模块化建筑、人工编排主要轮廓、实例化细节 |
| 远景区 | 城市延伸、远处天际线和大气 | 环绕低精度体块、低对比材质、距离雾 |

远景使用具有空间位置的简化建筑，不用一张正面城市画充当全部方向的背景。

## 三、美术资源与场景制作

### 3.1 先确定美术基准

制作白昼、暮色、入夜三张主视角色稿，并补充一张反向视角色稿。

白昼以图2的蓝色江水、暖色建筑、丰富云层和通透日照为依据；暮色强化暖光与冷色阴影；夜晚保留建筑结构，以暖色外滩、冷色天际线和有限的彩色倒影组织画面。

主视图通过后，固定建筑与江面的色彩关系、核心地标轮廓及比例、各类笔触尺度、近中远景对比度，以及纸纹、描边和晕染的强度。

主视角色稿先探索三种候选构图，再选择一版深化。后续资产沿用同一基准，避免各张生成图风格独立漂移。

### 3.2 image 资源制作流程

所有新增绘画类资源必须实际使用 image 工具生成，并记录来源；模型与程序效果单独记录制作方式。

1. 按对象和用途编写资源需求。
2. 使用已确认色稿作为视觉参考生成。
3. 检查结构、透视、色彩、透明边缘及重复痕迹。
4. 修整、拆分、排布纹理并对应模型表面。
5. 制作运行版本，保留未经覆盖的原图。
6. 在真实模型上检查正面、侧面、背面和不同光照。
7. 通过场景验收后标记为可交付。

单个资源连续三轮仍不合格时，记录具体失败原因，调整制作方法后再继续；不得用占位资源替代并标记完成。

### 3.3 资源包划分

| 资源包 | 制作要求 |
|---|---|
| 十三处地标 | 每处独立资产包，包含模型、立面、屋顶、装饰和夜间发光遮罩 |
| 外滩通用建筑 | 六种类型：柱廊、拱窗、装饰艺术、坡屋顶、砖石、公寓 |
| 现代通用建筑 | 六种类型：玻璃塔楼、板楼、阶梯楼、商业裙房、住宅、办公楼 |
| 植被 | 四种树冠轮廓及灌木素材，结合立体枝干与树冠体块 |
| 天空 | 三时段天空底色、可环绕云层与独立云朵 |
| 水体 | 细碎笔触、泡沫、船尾波和岸边水色遮罩 |
| 地面与街道 | 铺装、道路标记、岸墙及局部旧化 |
| 点景 | 船只、车辆、路灯、栏杆、码头和少量人物 |

数量表示资产类型与覆盖范围，不以图片总张数衡量完成度。一个建筑包可复用同一图集的多个区域。

### 3.4 贴图约束

- 地标贴图默认 2048 像素级图集；确实影响近景清晰度的局部允许 4096 像素级。
- 通用建筑与环境图集默认 1024—2048 像素级。
- 记录工具返回的实际尺寸，不将放大图片计为新增细节。
- 固定日照方向、强烈反光和环境倒影不烘入基础颜色贴图。
- 法线和几何相关遮罩从模型制作或烘焙得到，不将生成的彩色图当作准确法线。
- 透明资源验证有效 Alpha，检查白边、黑边与远距离闪烁。
- 原图、修整图与运行图分开保存；清单记录引用关系、提示词、版本和校验值。

### 3.5 建筑模型升级

十三处地标全部替换或重制，不只修饰正面。

- 东方明珠：球体比例、支撑结构、连接层、环形细节和塔针。
- 上海中心：扭转收分、顶冠、幕墙节奏和基座。
- 环球金融中心：楔形体量、真实孔洞、侧壁和顶部结构。
- 金茂大厦：退台比例、八角体量、檐口和尖顶。
- 其他现代地标：各自的塔楼组合、幕墙和裙房。
- 外滩地标：钟楼、穹顶、铜绿屋顶、柱廊、窗套及连续檐口。

轮廓、屋顶、柱廊等影响空间感的细节使用几何；小型雕饰和细密接缝使用贴图与法线。取消统一方块窗格覆盖所有建筑的做法。

近、中、远三档模型保持相同坐标、锚点和主要轮廓，以屏幕投影尺寸切换细节。

### 3.6 街区与城市延伸

- 核心滨江采用显式布局，人工编排建筑高度、朝向和街道节奏。
- 固定种子随机只用于次要街区内部变化。
- 首批目标约 180 栋配景，覆盖十二种基础类型。
- 相邻建筑避免完全相同的轮廓、立面和屋顶组合。
- 两岸增加连续树带、步道、码头与街道点景。
- 保留苏州河口、外白渡桥及两岸关系约束。
- 核心区外围增加低细节城市延伸，隐藏或移除可见厚底座侧壁。

建筑数量是容量预算。视觉覆盖不足时优先重排密度与体量，不能仅增加重复楼块。

## 四、渲染、镜头与接口改造

### 4.1 绘画材质与后处理

采用保留连续光照的材质基础，加入局部绘画控制，替换当前以简单卡通分阶为主的表现。

- 模型表面固定笔触与颜料变化，避免镜头转动时纹理漂移。
- 保留石材、玻璃、金属和植被的差异。
- 柔和色调过渡，避免生硬明暗分块。
- 深度、法线辅助生成低强度结构边缘，重点表现檐口与体块转折。
- 天空和远景轻微颜色融合，保护窗格、栏杆等高频细节。
- 纸纹按输出像素尺度控制，不覆盖界面文字。
- 限制晕染、颗粒与 Bloom，防止泛灰、发糊或过曝。

不将整屏模糊和纸纹叠加作为主要水彩实现。

### 4.2 光照与三时段

单一连续时段状态统一驱动天空、灯光、材质、窗灯、水体与界面。

- 白昼：暖色日照、偏冷阴影、明确受光层次。
- 暮色：低角度暖光、柔和天空和沿江初亮灯光。
- 入夜：天空与建筑分离，保留暗部结构，限制高亮面积。

保留约 2.4 秒可中断过渡，不移动用户相机。固定结构遮蔽可烘焙，三时段日照与窗灯不得烘死在同一基础贴图。

### 4.3 江水与倒影

复用平面反射基础，重做水面合成：基础颜色按岸边、航道及远近变化；两层不同尺度动态笔触；柔和扰动的可识别建筑倒影；船尾波绑定位置、方向和速度；夜间发光倒影有明确来源。

反射排除水面自身与无关透明对象。桌面精细档使用半尺寸反射目标，流畅档与手机使用简化反射；更新频率与主画面解耦。

### 4.4 镜头与展示界面

- 默认从南侧看向两岸，外滩为前中景、陆家嘴为天际线。
- 视场角 40°，初始俯视角约 25°，按核心区包围盒自动取景。
- 保留约 10% 主体安全边距，避免地标顶部被界面遮挡。
- 四个预设覆盖整体、陆家嘴、外滩与江面。
- 完整水平环绕，俯仰距水平约 12°—78°，缩放防穿模与暴露底部。
- 默认关闭自动环绕，用户可手动开启。
- 标题缩为角落标识，介绍收起为说明入口。
- 默认隐藏全量地标标签，选择、聚焦或主动开启时显示。

界面调整以让出画幅为目的，保留字体、配色与操作逻辑。

### 4.5 模块与接口

保留 `SceneControls` 方法名称与调用方式。

| 数据 | 必需内容 |
|---|---|
| 建筑资产描述 | 编号、模型路径、细节档、材质、包围盒、标签与聚焦锚点 |
| 场景布局实例 | 资产编号、位置、旋转、缩放、所属地标或街区、稳定种子 |
| 美术资源记录 | 制作方式、原图、运行文件、参考来源、尺寸、版本、校验值、验收状态 |
| 时段美术预设 | 天空、日光、环境光、曝光、雾、水色、窗灯与绘画强度 |
| 画质配置 | 分辨率、阴影、反射、细节档与后处理开关 |

- 十三处地标 ID 稳定。
- 标签与聚焦从模型锚点转换到世界坐标，不按高度估算。
- 合并、实例化及子节点可回溯地标，保证拾取与遮挡。
- 资源加载、场景组装、时段控制和渲染效果分为独立模块。
- 资源状态为概念、候选、已接入、已验收；加载成功不自动升级。

### 4.6 加载、异常与离线交付

按界面与轻量天空、核心地标与江面、核心街区、远景与高细节的顺序加载。

- 进度按实际阶段显示，不提前宣告完成。
- 核心资产缺失明确标记降级，替代模型不能通过美术验收。
- 次要资产失败保留可操作场景，记录失败编号。
- WebGL 恢复后重建反射与后处理资源。
- 释放时清理模型、纹理、目标和监听器。
- 资源随静态成品交付，不依赖远程图片地址或 CDN。

## 五、性能预算与实施顺序

### 5.1 性能目标

以下为目标，必须重新实测。

| 项目 | 桌面精细档 | 流畅档及手机 |
|---|---|---|
| 主要目标 | 完整美术表现 | 核心构图与交互 |
| 桌面绘制尺寸 | 1920×1080 | 1536×864 |
| 桌面持续帧率 | 中位数≥30 FPS，P95≤50 ms | 目标60 FPS，P95≤25 ms |
| 阴影 | 2048，核心区 | 1024或关闭次要投影 |
| 反射 | 半尺寸，最高20次/秒 | 四分之一或简化 |
| 绘画辅助通道 | 半尺寸深度、法线与轻量合成 | 减少通道与边缘效果 |
| 建筑细节 | 近中远三档 | 提前切低细节 |

- 核心首屏压缩资源≤40 MB，总运行资源≤150 MB。
- 桌面精细档估算纹理及渲染目标显存合计≤512 MB。
- 主场景可见三角形约150万以内，单次主通道绘制调用约400次以内。
- 分别记录主通道及包含阴影、反射、后处理的总成本。
- 优先优化图集、实例化、裁剪和更新频率，不暗降精细档分辨率。

样片记录设备、GPU、浏览器、绘制尺寸和体积，并固定为对照环境。实体手机无测试条件时标记未实测。

### 5.2 分阶段实施

| 阶段 | 工作内容 | 退出条件 |
|---|---|---|
| P0 基线 | 保存旧主视图、环绕图、功能与性能记录；建立美术验收表 | 旧版可复现，新旧记录分开 |
| P1 定调 | 候选、三时段和反向色稿，固定色彩与笔触 | 用户确认主视角色稿 |
| P2 工具链 | 模型导出、资源处理、清单与单体预览 | 单体加载、时段、细节与释放可用 |
| P3 局部样片 | 东方明珠、海关、原汇丰、两类配景、树带和江面 | 正反与三时段达标，用户视觉认可 |
| P4 地标 | 其余十处地标、专用美术与锚点 | 十三地标侧背面及近景达标 |
| P5 全城 | 十二类配景，街区、远景、岸线和点景 | 八方位无空白背面、阵列和断面 |
| P6 整体美术 | 统一天空、光照、绘画、水面与三时段 | 主视图及细节风格一致 |
| P7 优化回归 | 画质分级、性能、交互与异常回归 | 达到目标，差异有记录 |
| P8 交付 | 源码、原图、模型源、画册与报告 | 离线可运行，可追溯 |

P3 未通过时集中修正资产、渲染或构图，不批量复制到全城。

### 5.3 投入安排

建筑与专用美术40%；材质、光照、天空、水体25%；布局、街区、环境20%；优化、验收、交付15%。

不在样片前承诺全城固定工期。P3 后依据实际制作量和运行成本更新剩余工作量；增加投入不自动扩大到新功能或付费服务。

## 六、验证、视觉门槛与交付

### 6.1 视觉验收

固定八个水平角度、三个时段，共24张环绕图；另输出十三地标近景及无界面主画面。

固定机位、绘制尺寸及种子，支持并排比较。截图通过实际渲染链路输出，不用生成图替换，也不额外美化。

| 五分制维度 | 达标表现 |
|---|---|
| 构图与层次 | 主体清楚、景深层次连贯，无无效留白 |
| 建筑质量 | 可辨、屋顶立面丰富、侧背完整 |
| 绘画统一性 | 尺度一致，无贴纸、过度描边与模糊 |
| 光照与色彩 | 明暗冷暖清楚，三时段成立，无死白死黑 |
| 水体与天空 | 天空参与构图，水有层次，倒影来源明确 |
| 环境与环绕 | 街区连续、点景有尺度、各方向无穿帮 |

每项≥4分、平均≥4.2分且无严重穿帮。评分附截图与说明，不由测试自动推导。

主视角色稿、P3 样片和最终主画面需要用户视觉确认；日常资源按已定标准自行验收。

### 6.2 自动与功能验证

保留有效测试，并补充模型与贴图引用一致、ID唯一、锚点存在、河道关系、合并与实例拾取、连续时段切换、细节档切换、笔触稳定、截图一致、异常恢复、减少动态效果、横竖屏与持续运行资源释放检查。

类型检查、单元测试与生产构建后，从生产成品执行浏览器回归。

### 6.3 主要风险与处理

| 风险 | 处理 |
|---|---|
| 图漂亮但无法贴合模型 | 先做单体纹理对应及多角度检查 |
| 建筑各面不一致 | 按同一模型与材质基准修整，不直接拼接矛盾视图 |
| 仍像积木 | 联合检查体量、屋顶、密度与光照 |
| 水彩使画面变糊 | 分离笔触与后处理，保护结构细节 |
| 性能不足 | 实例化、图集、细节档、反射更新、辅助通道依次优化 |
| 暴露边界 | 完整街区及远景闭合，限制极端缩放 |
| 全城风格不统一 | 共用色稿、曝光、光照与笔触基准 |

### 6.4 最终交付物

计划与变更记录；完整源码与静态成品；Blender源文件、GLB与导出说明；image原图、修整图、运行图及记录；资源画册；三时段主视图、24方位与十三地标近景；新旧比较、视觉评分、功能及真实性能报告；启动、资源重建、画质与第三方声明。

### 6.5 完成定义

1. 完整360°、三时段与核心交互。
2. 图2方向的城市风景感，厚底座和灰色留白不再主导。
3. 十三地标与街区有明确造型、立面、材质差异。
4. image资源真实接入且可追溯。
5. 各方向与三时段通过视觉验收。
6. 功能、性能、完整性及离线交付分别达标。
7. 最终画面获得用户视觉确认。
